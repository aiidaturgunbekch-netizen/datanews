# DataNews — инструкция администратора

## 0. Нужно ли это настраивать?

Сайт — статическое приложение (Vite + React) плюс несколько серверных функций Vercel в папке `api/`.
Публичная часть (афиша, календарь, предупреждения) работает **без настройки**.

Для регистрации гостей, модерации, панели администратора и статистики нужно общее хранилище:
без него каждый посетитель видел бы только свои данные в своём браузере, а заявки гостей
никогда не дошли бы до вас. Поэтому обязательны:

| Что | Зачем | Обязательно? |
|---|---|---|
| **Upstash for Redis** (бесплатный тариф) | хранит пользователей, заявки, фото, статистику | да |
| **`ADMIN_PASSWORD`** | ваш пароль для входа в панель | да |
| **`AUTH_SECRET`** | ключ подписи входа; без него используется производный от пароля | желательно |

Новых npm-зависимостей нет: Redis вызывается через его REST API обычным `fetch`.

## 1. Настройка в Vercel (≈5 минут)

1. Откройте https://vercel.com → ваш проект **datanews**.
   **Сначала исправьте папку сборки.** Сейчас Vercel собирает сайт из старой копии
   `datanews-updated/datanews`, поэтому изменения из корня репозитория (включая панель
   администратора и папку `api/`) на сайт не попадают.
   **Settings → Build and Deployment → Root Directory → Edit** → очистите поле
   (корень репозитория, `./`) → **Save**. Framework Preset должен остаться **Vite**,
   Build Command — `npm run build`, Output Directory — `dist`.
2. **База данных:** вкладка **Storage** → **Create Database** (или **Browse Marketplace**) →
   **Upstash** → **Upstash for Redis** → тариф **Free** → регион ближе к Центральной Азии
   (например, Frankfurt) → **Create** → **Connect Project** → выберите `datanews`, окружения
   **Production** и **Preview** → **Connect**.
   Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` — вводить их вручную не нужно.
3. **Пароль администратора:** вкладка **Settings** → **Environment Variables** → **Add New**:
   - Key: `ADMIN_PASSWORD`, Value: ваш длинный пароль (12+ символов), Environments: Production и Preview → **Save**;
   - Key: `AUTH_SECRET`, Value: любая длинная случайная строка (например, 40 случайных букв и цифр) → **Save**.
   Никому не сообщайте эти значения и не записывайте их в код или в GitHub.
4. **Повторное развёртывание:** вкладка **Deployments** → у последнего развёртывания нажмите **⋯** → **Redeploy**.
   Переменные окружения применяются только к новым развёртываниям.

Проверка: откройте `https://<ваш-сайт>/#admin` и войдите паролем. Окно входа подскажет, чего не хватает:
«Сервер не видит базу данных» — не выполнен шаг 2 (или 4); «не задана переменная ADMIN_PASSWORD» — шаг 3 (или 4).

**Проверка базы без пароля:** откройте `https://<ваш-сайт>/api/auth?check=storage`.

| Ответ | Что значит |
|---|---|
| `{"storage":"ok"}` | база подключена и отвечает |
| `storage_not_configured` | для этой сборки не заданы `KV_REST_API_URL` / `KV_REST_API_TOKEN` |
| `storage_bad_url` | в `KV_REST_API_URL` не тот адрес: нужен REST-адрес `https://…upstash.io` из раздела **REST API**, а не `redis://…` |
| `storage_auth_failed` | токен не подходит: скопируйте **REST Token** этой же базы заново |
| `storage_readonly` | вставлен **Read-Only Token** — нужен основной REST Token |
| `storage_unreachable` | база не отвечает (удалена, другой адрес) |

Ответы не содержат адреса базы и токена. Кавычки и случайные пробелы вокруг значений сайт убирает сам.

**Подробный отчёт (только Preview).** На сборках Preview тот же адрес `…/api/auth?check=storage` показывает отчёт
без значений переменных; на Production — только краткий ответ выше.

| Поле | Что показывает |
|---|---|
| `deployment` | окружение (`preview`), ветка и первые 7 символов коммита сборки, которая ответила |
| `variables` | из каких переменных взяты адрес и токен (`urlFrom`, `tokenFrom`) и какие имена вообще заданы |
| `url.hostType` | `upstash-rest` — правильный REST-адрес; `upstash-console-page` — адрес страницы консоли; `redis-connection-string` — строка `redis://`; `other` — чужой домен |
| `url.hasPath` | `true` — после домена есть путь (у REST-адреса его нет) |
| `token.length` / `lengthAfterCleanup` | длина значения до и после снятия пробелов и кавычек по краям |
| `token.whitespaceInside`, `lineBreakInside`, `nonAsciiChars`, `variableNamePasted` | пробел или перенос внутри, нелатинские или невидимые символы (например, маска •••), вставленное имя `ИМЯ=` |
| `upstash.httpStatus`, `upstashError` | HTTP-статус и короткий текст ответа Upstash (токен и адрес в нём скрыты) |
| `upstash.sendError` | запрос не ушёл: `header` (перенос строки в токене), `invalid_char` (недопустимый символ), `network` (база не отвечает) |
| `conclusion` | короткий вывод по этим фактам |

Длину токена можно сверить с консолью Upstash, не пересылая его: скопируйте токен в любой счётчик символов у себя
или просто сравните с тем, что токен в Upstash — одна строка без пробелов.
Подробности ошибки видны в логах Vercel: **Deployments → сборка → Logs** (строки `[storage] …`).

### Только для Preview (не затрагивая Production)

Вместо шага 2 можно создать базу в консоли upstash.com (тариф Free) и добавить переменные вручную:
**Settings → Environment Variables → Add New**, окружение — только **Preview**:

| Имя | Значение |
|---|---|
| `KV_REST_API_URL` | REST URL базы из консоли Upstash (раздел REST API) |
| `KV_REST_API_TOKEN` | REST токен базы оттуда же (секрет) |
| `ADMIN_PASSWORD` | пароль для входа в панель (секрет) |
| `AUTH_SECRET` | длинная случайная строка (секрет, желательно) |

Можно использовать и имена `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` — сайт понимает оба варианта;
если заданы оба, используются `KV_REST_API_*`.

Если переменные привязаны к конкретной ветке Preview, имя ветки должно совпадать **символ в символ**
(например, буква `l` и цифра `1` различаются). Иначе переменные к сборке этой ветки не применятся.
После добавления переменных — **Redeploy** именно сборки Preview.

Не добавляйте в Vercel переменную `DATANEWS_MEMORY_KV`: она только для локальной разработки
и включает тестовый пароль.

## 2. Где вы управляете сайтом

Панель открывается **только по адресу**:

```
https://<ваш-сайт>/#admin
```

Обычный адрес сайта (без `#admin`) всегда открывает публичную главную страницу.
Гости кнопку панели не видят — у них в шапке «Войти» и «Разместить».
После входа в шапке появляется зелёная кнопка 🛡 «Панель управления».
Права проверяет сервер: без вашего пароля ни один запрос к модерации, пользователям
или статистике не выполнится, даже если кто-то найдёт адрес `#admin`.

Личный кабинет пользователей: кнопка «Войти» в шапке или адрес `https://<ваш-сайт>/#login`
(`#cabinet` — сразу кабинет). В одном браузере действует один вход: если вы вошли
в панель, вход в кабинет завершит сеанс администратора в этом браузере
(для проверки кабинета удобно открыть второе окно в режиме инкогнито).

### Доступ для сотрудников и помощников

Каждому человеку — отдельная учётная запись обычного пользователя. Панель управления
ему недоступна; он размещает публикации на модерацию в пределах тарифа своей учётной записи.

1. Панель → «Пользователи» → «Учётная запись для сотрудника»: имя, организация (от чьего
   имени будут публикации), e-mail, телефон, пароль, тариф → «Создать учётную запись».
2. Создание учётной записи **бесплатное**: она сразу сохраняется со статусом «Не оплачено»,
   платный период автоматически не начинается, деньги не списываются (платёжный сервис не подключён).
3. Передайте сотруднику e-mail и пароль лично. Он входит кнопкой «Войти» на сайте.
   Без оплаченного периода он может войти в личный кабинет и работать со своими публикациями,
   но не может отправлять новые публикации на размещение.
4. «Подтвердить оплату (30 дней)» нажимайте **только после фактически полученной оплаты** тарифа:
   кнопка лишь отмечает оплату и открывает 30-дневный период, сама ничего не списывает.
5. Если сотрудник забыл пароль или больше не работает — «Новый пароль» в его карточке:
   прежний пароль и все его открытые входы сразу перестают действовать.
   Остановить размещение — «Приостановить» (тариф).

Сотрудник не может: открыть панель, управлять пользователями, тарифами и оплатой,
одобрять публикации (в том числе свои), присвоить себе статус госоргана,
публиковать в официальные разделы, обойти лимит тарифа.

| Вкладка | Что делать |
|---|---|
| **Модерация** | Новые публикации гостей с фото, датой, адресом и контактами автора: **Одобрить** (сразу на сайте), **Отклонить** (с причиной — автор её увидит), **Исправить**. «Одобрить» разрешает публикацию, но не подтверждает достоверность. |
| **Сверка с источниками** | Действующие публикации, которые нужно сверить: давно не сверялись, **не подтверждены**, нет ссылки на первоисточник, не проверена ссылка на билеты, у закона нет документа или даты. **Проверено сегодня** обновляет только дату сверки. Отметку **Подтверждено по первоисточнику** ставит редактор в форме публикации после проверки источника; сохранение формы, правка текста или фото и одобрение её не ставят. |
| **Публикации** | Все события сайта: поиск, редактирование, удаление, **Новая публикация** (ваши выходят сразу), **История изменений**, **Снять с публикации** / **Вернуть на сайт**. Публикации госорганов помечены «Госорган, без премодерации». |
| **Пользователи** | Тариф, текущий 30-дневный период, сколько публикаций использовано и осталось, история оплат. **Подтвердить оплату (30 дней)**, **Продлить на 30 дней**, **Приостановить**, **Платёж не найден**; для госорганов — заявка на статус: **Подтвердить статус**, **Отклонить**, **Отозвать статус**. |
| **Жалобы** | Жалобы читателей: **Проверено, оставить** или **Снять публикацию**. |
| **Статистика** | Посетители и просмотры за сегодня / 7 / 30 / 90 дней, график, разделы, источники переходов, города, устройства, язык. Ваши визиты и роботы не считаются. |

## 3. Оплата и тарифы — все на 30 дней

| Тариф | Цена | Лимит за 30 дней |
|---|---|---|
| **Старт** | 2 000 сом / 30 дней | до 3 публикаций |
| **Частный** | 5 000 сом / 30 дней | до 8 публикаций |
| **Культура и театр** | 1 000 сом / 30 дней | без лимита, но **только раздел «Театр и культура»** (сервер не даёт публиковать в других разделах) |
| **Организатор** | 10 000 сом / 30 дней | без общего лимита, но **не более 1 новой публикации в календарный день** по времени Кыргызстана |
| **Муниципалитет / государственный орган** | 2 000 сом / 30 дней | без лимита; только после подтверждения статуса (см. раздел 3а) |

Как это работает (проверяет **сервер**, `api/_lib/quota.ts`, а не только кнопки):

- Каждое подтверждение оплаты создаёт **период на 30 дней** с датой начала и окончания. Все периоды
  хранятся — это история платежей (видна вам во вкладке «Пользователи» и пользователю в кабинете).
- Лимит считается **внутри периода**. Неиспользованные публикации **сгорают**; новый период начинается с полным лимитом.
- Лимит **не сбрасывается 1-го числа** — только с началом нового оплаченного периода (например, 14.10 → 13.11).
- **Продление заранее**: если подтвердить оплату, пока период ещё идёт, новый период начнётся сразу после окончания текущего — дни не теряются.
- После окончания 30 дней публиковать нельзя, пока вы не подтвердите новую оплату.
- «Организатор»: вторая публикация в тот же день отклоняется (атомарно, Redis `SET NX`), даже при повторной отправке или обновлении страницы.
- Публикация засчитывается в момент отправки; отклонённая модератором лимит не возвращает. Исправление своей публикации лимит не тратит.
- **Приостановить** — период прекращается сейчас, история остаётся.
- Пользователи старых тарифов: «basic» → «Частный», «business» → «Организатор»; их оплаченный срок сохраняется как один период.

Цены, названия и описания — в **`src/config/site.ts`** (`PLANS`). **Реквизиты** — `PAYMENT_DETAILS` (сейчас пусто:
гостю пишется «Администратор свяжется с вами и пришлёт реквизиты»).

Оплата **ручная** (на сайте это прямо написано): гость переводит деньги и вводит номер транзакции,
вы сверяете и нажимаете «Подтвердить оплату». Онлайн-оплата (MBank, O!Деньги, Элсом, Finik и др.) не подключена:
нужен договор с платёжной системой — подключается отдельно и только после вашего решения.

## 3а. Госорганы и муниципалитеты — без предварительной модерации

1. Организация регистрируется и в «Профиле и оплате» подаёт **заявку на подтверждение статуса**:
   официальное название, должность, официальный сайт, служебный e-mail, номер и дата официального письма / приказа.
2. Вы проверяете во вкладке «Пользователи»: домен почты совпадает с официальным сайтом, письмо пришло со
   служебного адреса, документ подписан руководителем. **Название аккаунта само по себе ничего не подтверждает** —
   статус никогда не присваивается автоматически.
3. **Подтвердить статус** → затем **Подтвердить оплату** тарифа «Муниципалитет / госорган» (без подтверждённого статуса
   сервер не даст активировать этот тариф и не даст его выбрать без заявки).
4. После этого публикации организации **выходят сразу**, минуя очередь модерации, с пометкой
   «Официальная публикация организации. Организация самостоятельно отвечает за достоверность сведений».
   В кабинете организации это же предупреждение показано постоянно.
5. Проверки остаются: обязательные поля, запрет дублей, не более 10 публикаций в час, жалобы читателей,
   **история изменений** у каждой публикации (кто и когда создал, изменил, снял), кнопка **«Снять с публикации»**
   (у вас — для любой публикации, у автора — для своей), **«Вернуть на сайт»**, **«Отозвать статус»** — после отзыва
   публикации снова идут через модерацию.

## 3б. Жалобы

У каждого события есть кнопка **«Пожаловаться»** (причина, комментарий, контакт). Вкладка **«Жалобы»**:
«Проверено, оставить» или «Снять публикацию» (автор увидит причину). Встроенные редакционные события
снимаются кнопкой «Удалить» во вкладке «Публикации».

## 4. Путь гостя

1. «Личный кабинет» / «Разместить» → **Регистрация**: имя, e-mail, телефон, пароль, тариф.
2. Оплата и ввод номера транзакции → статус «Оплата проверяется».
3. Вы подтверждаете оплату → начинается 30-дневный период. В кабинете видно: даты периода, сколько публикаций осталось, история оплат.
4. Гость заполняет **единую форму** (категория, заголовок, дата и время, место, описание, контакты, своё оригинальное фото
   или афиша, ссылка на источник, дата окончания) и смотрит **предпросмотр** в фирменном шаблоне.
   Фото до 650 КБ сохраняется **без изменений**; большее — только уменьшается с сохранением пропорций. Сайт не обрезает
   и не меняет изображение автора.
5. Публикация уходит на модерацию («На модерации»); вы одобряете или отклоняете с причиной.

Гость не может сам включить бегущую строку «Срочно», отметку «Проверено» или «Ссылка на билеты проверена».

## 4а. Источники и билеты

- **Билеты**: сначала GovTicket (ticket.gov.kg), если событие там есть; затем сайт организатора; затем проверенный
  частный сервис (Kassir.kg, Ticket.kg и др.). Кнопка «Купить билет» ведёт на страницу конкретного события и
  показывается только после отметки «Ссылка на билеты проверена». GovTicket подписан как государственный сервис,
  частные — как частные.
- **Предупреждения и госсобытия**: сначала сайт мэрии / ведомства / службы, затем первоисточник организатора,
  и только потом СМИ. В форме администратора укажите, чем является ссылка («Официальный источник», «Организатор»,
  «Билетный сервис», «СМИ»), дополнительный источник и официальный сайт ведомства.
  Если официального сообщения нет, карточка прямо пишет: «Официальное сообщение не найдено — сведения из СМИ».
- В карточке ссылки разделены: «Официальный источник» / «Ответственное ведомство», «Организатор», «Купить билет», «Дополнительный источник».

## 4б. Откуда берутся события в календаре

- **Вручную (редакция):** `src/data/initialAnnouncements.ts` и ваши публикации из панели — со ссылкой на источник и датой проверки.
- **От пользователей:** после модерации; **от подтверждённых госорганов:** сразу.
- **Автоматически:** не подключено (поля `dataOrigin: 'auto'` и `lastCheckedAt` зарезервированы).
- Истёкшие предупреждения автоматически скрываются из активных списков.
- Фото: официальные афиши организаторов загружаются через панель (кнопка «Загрузить» или ссылка на изображение).
  Где афиши нет — реальное архивное фото объекта с Wikimedia Commons с подписью «не снимок этого события»
  или тематическая иллюстрация. Лица людей не генерируются и не изменяются.

## 5. Что проверить перед публикацией

- Контакты редакции (WhatsApp, Telegram, Instagram) заданы в `src/config/contacts.ts`.
  Telegram сейчас открывается по номеру телефона (`t.me/+996700230994`) — это сработает, только если
  в настройках Telegram разрешён поиск по номеру. Если у вас есть публичное имя (@username) —
  впишите его в поле `telegramUsername`.
- Встроенные события взяты из открытых источников (ссылки — в карточке каждого события).
  Перед запуском сверьте даты и цены у организаторов.

## 5а. Погода и безопасность

- На главной показывается **только подтверждённое**: официальные предупреждения и официальный прогноз
  Кыргызгидромета по областям (если вы его внесли). Если их нет — остаётся одна строка с номерами 112, 101,
  102, 103 и телефоном синоптика Кыргызгидромета. Автоматический прогноз MET Norway и блок перевалов
  с сайта убраны (код сохранён — их можно вернуть позже).
- **Вручную:** официальные предупреждения Кыргызгидромета и МЧС — публикация категории
  «Опасные явления» с уровнем опасности (красный / жёлтый / информация). Закрытие дорог и перевалов —
  только по сообщению МТД, МЧС или УОБДД (ссылку на ведомство — в источник).
  У Кыргызгидромета нет API или RSS, поэтому автоматического получения предупреждений нет.
- **Официальный прогноз Кыргызгидромета** (раз в день): панель → **Прогноз погоды** → вставьте
  текст сводки (с meteo.kg или из СМИ со ссылкой на Кыргызгидромет) → **Заполнить таблицу из текста** →
  проверьте цифры и дату → вставьте ссылку на сообщение → **Сохранить**. Он показывается на главной
  с пометкой «Официальный прогноз Кыргызгидромета» и ссылкой; на прошедшую дату сам скрывается.
- Истёкшие предупреждения сами уходят в архив по дате окончания.

## 5б. Государственные решения и законы

- В форме администратора есть поля «Вид материала» (решение, заявление, поручение, встреча, закон…)
  и «Правовые сведения»: даты принятия, официального опубликования и вступления в силу, что изменилось,
  кого касается, что делать, переходный период, ссылка на официальный текст (cbd.minjust.gov.kg).
- Если дата вступления в силу не известна — оставьте поле пустым: сайт напишет «дата не указана»,
  а не «действует». Заявления и обещания отмечайте как «заявление», не как «решение».
- **Повторы:** при добавлении сайт проверяет, нет ли уже публикации с той же ссылкой на источник или
  с той же датой и почти тем же заголовком, и спрашивает подтверждение.
- Значок «Перепроверить» — у действующей публикации последняя проверка была более 3 дней назад.

## 5в. Реестр источников

Страница «Источники информации» (ссылка в подвале) и `/api/sources` показывают все источники:

## 5г. Чат-бот DataNews AI — бесплатный, без внешнего ИИ

Бот работает на сервере сайта (`api/assistant.ts`, логика — `api/_lib/bot.ts`) и **не обращается к платным
ИИ-сервисам**: ключи API не нужны, оплаты за ответы нет.

- Темы (кнопки): новости сегодня, по регионам, погода, штормовые предупреждения, перевалы, госновости,
  законы, концерты и кино, билеты, как разместить, тарифы, контакты.
- Понимает в вопросе даты («сегодня», «завтра», «послезавтра», «выходные», «на этой неделе», «в этом месяце»,
  «в ноябре», «31 октября»), города и области, темы — на русском, кыргызском и английском.
- Отвечает только данными сайта: опубликованные материалы и официальный прогноз, который вы вносите
  (панель → «Прогноз погоды»). Если данных нет — прямо говорит об этом и даёт ссылку на раздел или источник.
- Вопросы не сохраняются; история переписки — только в браузере посетителя до закрытия вкладки.
- Защита от перегрузки: не более 40 вопросов за 10 минут с одного адреса.

## 5д-1. Карта Кыргызстана

Блок «Обзор по городам» → «Карта Кыргызстана» (`src/components/KyrgyzstanLiveMap.tsx`):

- **Подложка — OpenStreetMap** (бесплатно, обязательна подпись © OpenStreetMap — она стоит в углу карты):
  дороги, улицы, реки, сёла и города; чем ближе, тем больше деталей (до уровня улиц и домов, если они есть в OSM).
- **Границы поверх карты:** 7 областей и 41 район (geoBoundaries, ODbL) и граница Бишкека.
  Отдельной границы г. Ош в открытых данных нет — Ош отмечен точкой.
- **Фильтр:** область / город → район → населённый пункт. Населённый пункт ищется в OpenStreetMap (Nominatim)
  только по кнопке «Найти»; карта приближается к найденному месту.
- **Публикации:** для области — по полю «регион» публикации; для района и села — по полям «район»,
  «населённый пункт» и месту проведения. Поэтому указывайте район и населённый пункт в публикациях.
  Публикации на карте не ставятся точками: координат у них нет, и выдумывать их нельзя.
- Правила OpenStreetMap: бесплатно при умеренной посещаемости. При очень большой нагрузке нужен коммерческий
  поставщик тайлов — это решение за вами.
